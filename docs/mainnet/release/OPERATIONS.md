## Owner wallet sequence

`script/mainnet/PrepareOwnerTransactions.s.sol` is a local, read-only script, not a deployed companion. It returns `WalletTransaction[]` with explicit `chainId`, `from`, `to`, `value`, exact ABI calldata and expected effect. All calls have chainId1, value0 and the named owner as sender. It does not read keys, sign or broadcast.

Required inputs are the **actual** hook/launch number/native distributor/staged source and the complete native-tree leaves in heap leaf order. `Expected.owner` and `Expected.payer` come from the paid request. `Expected.hookRuntimeHash` must come from independently reconstructing the final accepted runtime with its resolved immutables and comparing it to deployed code. Merely copying an arbitrary target's `codehash` into Expected is not verification. `ARTIFACTS.json` contains runtime templates and immutable offsets; a template hash is not a deployed immutable-resolved hash.

1. Run `sourceTransaction(hook, launchNumber, expected)` against verified stage1 state. It checks the hook runtime, factory/manager/router/quoter/Permit2/IMD/fees/registry pins, launch record, LP principal, paid owner and payer. Sign its returned transaction to the actual hook: `deployPriceSource(final ImdSpotUsdSource creationCode, empty bytes)`. Confirm the receipt and read `stagedPriceSource()`; trading remains inactive.
2. Run `transactions(config, expected, recipients, amounts)` against that state. It verifies the staged source runtime/current valid price and the actual distributor's complete round0 root,100M funding, unique nonzero recipients and exact sum. It predicts the next companion addresses from the actual staging counter.
3. Sign the first returned call to the hook: `deployCompanions(number, source, finalCodes)`. Confirm the staged evidence/oracle/vault/verifier addresses and runtime bindings against the plan. Do not interleave another staging transaction; regenerate if the staging counter changes.
4. Sign the returned certification calls to the predicted evidence contract. Up to1024 recipients use `certifyRound(0, recipients, amounts)`. Larger trees use ordered256-leaf `submitLeaves` calls then256-node `reduce` calls until certified. The tests execute a1025-recipient tree through all11 remaining calls. Estimate gas against the actual tree before stage1; do not assume this local test proves an arbitrary tree fits one transaction.
5. Recheck the actual source price and all stage2 bindings, then sign the final returned `configureAndActivate(evidence, oracle, number)` call to the hook. This single transaction atomically verifies current price, native distributor/tree, factory/registry provenance, currencies, fees, seed/liquidity and companion commitments, binds the oracle and permanently activates/seals setup. Any invalid check reverts activation. No warm-up, samples or recording transactions exist.

The script ABI signatures are `sourceTransaction(address,uint64,(address,address,bytes32))` and `transactions((address,uint64,address,address),(address,address,bytes32),address[],uint256[])`. Use `forge script script/mainnet/PrepareOwnerTransactions.s.sol:PrepareOwnerTransactions --rpc-url <explicit-mainnet-rpc> --sig <signature> <actual-arguments>` **without `--broadcast`** to prepare them. The script constructor creates a verifier only in the local simulation. The returned calls, not deployment of the script itself, go to the wallet. There is no populated public transaction package yet because stage1 identities have not been assigned/deployed; no dummy target or calldata package is delivered as executable mainnet data.
